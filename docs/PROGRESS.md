## Текущее состояние (2026-10-24, версия 0.9.0 — волны 0, 1, 4, 4½, 4¾ и основное из волн 2 и 3 выполнены)

**MVP собран и работает локально.** Есть веб-приложение, в котором можно:
загрузить тексты → объединить их в корпуса → загрузить словарь и проверить разборы слов →
получить частоты, конкорданс, синтаксический профиль слова (члены предложения, однородные ряды),
сравнение корпусов, структуру предложений, **сводный отчёт по выбранным словам** → выгрузить всё в XLSX / CSV / JSON / CoNLL-U.
С версии 0.3.0: общая панель «Выборка» (корпус → флажки текстов, авторы, жанры, годы, тип) и выбор слов флажками для всех вкладок и выгрузок,
вкладка «📋 Отчёт», стоп-слова (встроенный список и свои), отмена и удаление фоновых задач, защита от падений обработчика.
С версии 0.4.0: **двухступенчатая обработка** — весь текст быстро разбирает Natasha, Stanza — только предложения со словами словарей
(на демо-словаре «Запахи» это ~1 % предложений «Войны и мира»); кнопки «Точный разбор» для текста и предложения.
С версии 0.5.0: вкладки **«Коллокации»** (окно и синтаксис, 9 мер ассоциации включая ΔP, орбитальный граф, сводная матрица мер),
**«Ключевые слова»** (keyness G²/log-ratio против опорного корпуса, облако, TF-IDF по текстам) и **«Карта текста»** (тепловая карта
словаря по отрезкам с показом отрезка по щелчку, лексическая дисперсия, DP и D Жуйяна).
С версии 0.6.0 (волна 3, без новых зависимостей — модели внутри пакета natasha): вкладки **«Имена»** (персоны / места / названия с начальной
формой, указатель, ручные правки, сеть персонажей, «имена × словарь»), **«Семантика»** (похожие слова navec с добавлением в словарь, смысловая
карта словаря, употребления слова — кластеры контекстов) и **«Темы»** (NMF).
С версии 0.7.0 (волна 4): вкладки **«Авторство»** (Delta / Cosine Delta по MFW, тексты или фрагменты, дендрограмма, карта, «кто автор?»)
и **«Сравнение текстов»** (метрики рядом, лепестковая диаграмма, общая/особая лексика, Жаккар, Cosine Delta), страница **«Проверка текста»**
(объяснимые признаки машинного текста, калибровка на текстах базы, честная точность, оговорка «не доказательство»).

## Упрощения относительно ТЗ (осознанные, для MVP)

1. **Один пользователь** (логин/пароль из `.env`) вместо ролей и регистрации. Для одного исследователя достаточно; многопользовательский режим — в бэклоге.
2. **Очередь задач в таблице `jobs`** вместо Celery + Redis: на два контейнера меньше, проще деплой. Для одного пользователя производительности хватает.
3. **Синтаксический слой пересчитывается на лету** при сопоставлении словаря (а не хранится для всех токенов в `token_edges`): в БД хранится базовое UD-дерево, а роли и связи — только для вхождений словаря (`dictionary_hits`, `token_relations`). Меньше места, правила можно улучшать и просто нажать «Пересчитать».
4. **Сохранение анализа = ссылка**: все параметры анализа в адресе страницы, его можно сохранить в закладки или отправить.
5. **Нет**: многословных выражений в словаре, оконных коллокаций (±N слов), свободного SQL, NER/тональности/эмбеддингов, разрешения анафоры, PDF-отчёта, загрузки .epub. Всё — в бэклоге ниже.
6. **Natasha** добавлена как второй парсер: модели входят в pip-пакет, работает без интернета и на слабом VPS. Качество синтаксиса заметно ниже Stanza (видно на сложных предложениях) — для исследования использовать Stanza.

## Известные ограничения

- Качество ролей и связей ограничено качеством парсера. Ошибки парсера видны на странице предложения (дерево + таблица); вхождение можно отметить как ложное (✗).
- Омонимия: «духи» по умолчанию → лемма «дух». Исправляется на экране верификации словаря (выбрать вариант или режим «по формам»), но формы «духи/духов» совпадают у обоих слов — нужна ручная проверка в конкордансе.
- Граница «дополнение / обстоятельство» для `obl` определяется по предлогу и падежу (§5.2), словаря управления глаголов пока нет.
- Разбор всего корпуса (101 МБ) на CPU займёт много часов (Stanza) — делайте пачками или на мощной машине, затем перенесите базу на VPS (DEPLOY.md, раздел «Перенос базы»).

3. ✅ (0.8.0) **Подписи на графиках (1 день).**

### План развития по заметкам с собрания разработчиков (2026-10-16)

**Принципы.** Платформа остаётся лёгкой: ядро работает на CPU и 4 ГБ памяти; всё тяжёлое (эмбеддинги, BERT, NER, Stanza) — **подключаемые модули** (отдельный файл зависимостей и профиль Docker), которые можно не ставить. Каждая новая функция встраивается в общую схему «**Портрет объекта в выборке**» (см. ниже) и в стартовую страницу, а не появляется отдельной вкладкой. Стоп-слова, фильтры и меры — **параметры просмотра**, исходные данные в БД не удаляются.

#### Единая модель интерфейса: «Портрет [чего] в [какой выборке]»

| Объект ↓ / выборка → | весь корпус | тексты по фильтрам (авторы, жанры, годы, тип, флажки) | один текст |
|---|---|---|---|
| **Текст / корпус** — размер, лексика, TF-IDF и ключевые слова, морфология, синтаксис, сущности, стилометрия | ☐ | ☐ | ✅ (портрет текста) |
| **Словарь (тема)** — частоты, ipm, дисперсия, карта по тексту, роли, семантические группы | ◐ (частота, обзор) | ◐ (фильтры только во «Обзоре») | ☐ |
| **Слово** — формы, роли, связи, коллокации (матрица мер, орбитальный граф), дисперсия, контексты | ◐ (профиль) | ☐ | ☐ |
| **Предложения со словом (словами)** — длина, тип, глубина, причастные/деепричастные обороты, однородные ряды, позиция слова, кластеры контекстов | ◐ (структура) | ☐ | ☐ |

Технически это одна панель «Выборка» (бэклог 2026-10-15, п. 3) + выбор объекта; любой портрет экспортируется (XLSX, CSV, позже HTML/PDF).

#### Стартовая страница «Что хотите сделать?»
Карточки-сценарии вместо списка разделов; каждая ведёт в мастер из 3 шагов (что исследуем → на каком материале → отчёт):
1. **Изучить слово** — как употребляется, с чем сочетается, где встречается (портрет слова, конкорданс, орбитальный граф).
2. **Изучить тему (словарь)** — «запахи», «цвета»…: частоты, карта по тексту («самые пахучие места»), семантические группы.
3. **Портрет текста или корпуса** — статистика, ключевые слова, сущности, стиль.
4. **Сравнить тексты или корпуса** — панель сравнения, автор ↔ автор, эпоха ↔ эпоха, человек ↔ нейросеть.
5. **Кто автор?** — стилометрия, атрибуция.
6. **Признаки машинного текста** — отчёт для преподавателя (с оговоркой «не доказательство»).
7. **Сравнить переводы.**
8. **Найти и выгрузить примеры** — предложения со словами в XLSX / CoNLL-U.
Плюс: демокорпус при первом входе, статус обработки текстов человеческим языком, подсказки к терминам (ipm, logDice, MATTR, PMI…).

#### Волна 1. Двухступенчатая обработка — главное ускорение ✅ (0.4.0, с уточнением ниже)
> **Как сделано (отличие от первоначального замысла):** замер показал, что первая ступень «только морфология» (pymorphy3, 63 с на «Войну и мир»)
> почти не быстрее Natasha с полным синтаксическим деревом (81 с). Поэтому ступень 1 — **Natasha с деревом** (`FAST_PARSER`), уровень разбора
> `sentences.parse_level = 1`; ступень 2 — основной парсер (`NLP_BACKEND`, Stanza), `parse_level = 2`. Плюсы: у всех предложений есть дерево
> (портрет, структура, страница предложения работают сразу), выборка-образец для синтаксических метрик не нужна. Токенизация на обеих ступенях
> одинаковая — строки `tokens` обновляются на месте (`app/services/deepparse.py`, временные таблицы + COPY), id токенов и вхождения сохраняются.
> Кандидаты для ступени 2 — все формы слова (все омонимичные лексемы) или совпадение предварительной леммы; вхождения ищутся только при `parse_level = 2`.
> Режим `PROCESSING_MODE=full` — как раньше. Ниже — исходный план для справки.
Сейчас каждый текст сразу целиком проходит синтаксический разбор Stanza — это самое долгое. Новый порядок:
1. **Ступень 1 (для всех предложений, быстро):** извлечение текста → нормализация → предложения → токены → лемма, часть речи, граммемы (pymorphy3) → лексико-морфологическая статистика, TF-IDF, стилометрия, поиск кандидатов из словарей. В разы быстрее Stanza.
2. **Ступень 2 (только для предложений с токенами из словарей):** синтаксический разбор Stanza → снятие омонимии, роли, связи, однородные ряды.
- Сопоставление со словарём на ступени 1 идёт по всем возможным леммам pymorphy (с запасом), ступень 2 уточняет и отбрасывает ложные (например, «стали» — «сталь» / «стать»).
- Новый словарь → разбираются только **новые** найденные предложения (дозагрузка).
- Синтаксические метрики портрета (глубина, MDD, придаточные) — по выборке предложений (например, 2000) или по кнопке «Полный разбор текста».
- В БД: `sentences.parse_level` (0 — только морфология, 1 — синтаксис), `tokens.head/deprel` допускают NULL; миграция Alembic; всё, что требует синтаксиса, понимает уровень разбора.
- Ожидаемый выигрыш: если словарные слова есть в 5–10 % предложений, разбор корпуса быстрее в 10–20 раз. Замерить на «Войне и мире».

#### Волна 6. Генерация текстов по связям из корпуса (эксперимент, после волн 1–3)
Идея пользователя: «Кавказ у Лермонтова — запах»: извлечь из корпуса русской литературы связи и научить нейросеть писать маркетинговые тексты (чай, вино, парфюм).
- **Платформа даёт главное — структурированную «сенсорную базу»**: для каждого слова-ощущения — источники (*сирень, дым*), качества (*сладкий, пряный, горький*), действия (*стоял, разливался, кружил голову*), воздействие, места (NER), с цитатами и авторами. Это и есть исследовательский результат, его можно публиковать.
- **Шаг 1 — без дообучения (RAG):** по ключевым словам («чай, бергамот, вечер») платформа подбирает подходящие связи и цитаты и передаёт их готовой языковой модели по API (GigaChat / YandexGPT / Claude / открытая Qwen) с заданием «напиши текст в духе русской прозы». Дёшево, без GPU, прозрачно (видно, откуда взяты образы), меняется за минуты.
- **Шаг 2 — дообучение LoRA (только если шаг 1 не устраивает):** небольшая открытая модель (7–8 млрд параметров), аренда GPU на несколько часов (порядка 1–5 тыс. руб.); пары «ключевые слова → текст» придётся сначала сгенерировать (шаг 1) и отобрать вручную — литературные предложения сами по себе учат стилю, а не жанру рекламы. Отдельный сервис, не часть ядра.
- Ассоциативные цепочки строятся из корпуса (синтаксическая сочетаемость + navec) — это функция ядра, а не нейросети.
- Тексты XIX века — общественное достояние; для современных корпусов проверять права.

## Принятые решения

- Порядок работ — вертикальный срез сначала, потом наращивание слоёв.
- Грамматическая традиция для членов предложения — академическая («Русская грамматика» 1980), см. §5.6 ТЗ.
- Старые пароли из истории Git считаются скомпрометированными (репозиторий публичный) и больше не используются; сервер pgadmin.quotverba.ru выключен.
- Стек: FastAPI + Jinja2 + Plotly, PostgreSQL 16, SQLAlchemy 2 + Alembic, очередь задач в БД, Docker Compose + Caddy.
- Парсер по умолчанию — Stanza; запасной — Natasha (`NLP_BACKEND`).
- «Индексы каузальной зависимости» = направленная мера ассоциации ΔP (2026-10-16).
- Сравнение переводов — пары «оригинал на другом языке ↔ русский перевод» (2026-10-16).
- Многоязычность — через языковые профили поверх UD; новые языки и переводы — только после замера точности на русском эталоне (ТЗ §19).
